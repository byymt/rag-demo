# 第一阶段学习笔记：从 LLM API 到完整 RAG

## Day 1 单轮对话（01_llm_single.py）

调用大模型 API 的三要素：**URL（接口地址）、API_KEY（鉴权）、model（模型名）**。

- 接口是 OpenAI 兼容格式：`POST {base}/compatible-mode/v1/chat/completions`
- 请求头：`Authorization: Bearer <KEY>`（注意 Bearer 拼写，曾写成 Beared 导致 401）
- 请求体：`model`、`messages`、`temperature`（越小输出越稳定）
- `messages` 的 role 三种：`system`（人设/规则）、`user`（用户）、`assistant`（模型回答）
- 取回答：`resp.json()["choices"][0]["message"]["content"]`（choices 是复数，曾漏 s 报 KeyError）

## Day 2 多轮对话 + 流式输出（02_llm_multi_stream.py）

- **多轮的本质**：把历史对话全部放进 `messages` 再发过去，模型本身不记事，上下文靠客户端维护
- **流式**：`stream=True`，用 `with requests.post(...) as resp` + `resp.iter_lines()` 逐行读
- 每行形如 `data: {...}`，去掉前缀后 `json.loads`；`data: [DONE]` 表示结束
- 增量文本在 `chunk["choices"][0]["delta"]["content"]`（流式是 delta，非流式是 message）
- 踩坑：某个 chunk 的 `choices` 可能是空列表（用量统计块），取 `[0]` 前要判空，否则 list index out of range
- 踩坑：从网页复制的代码可能带全角连字符 `‑`（U+2011），肉眼难辨但会让 `decode("utf-8")` 直接报错

## Day 3 FastAPI 接口 + SSE（03_fastapi_chat.py）

- `app = FastAPI(title=...)`，参数要写关键字，不能把 title= 塞进字符串
- `@app.post("/chat/stream")` + Pydantic 模型做请求体校验（`class ChatReq(BaseModel)`）
- 流式返回用 `StreamingResponse(gen(), media_type="text/event-stream")`，生成器里 `yield f"data: {text}\n\n"`
- 测试：Apifox POST + JSON body；选 SSE/事件流模式看逐条消息
- 改代码后必须重启 uvicorn 才生效；开发期可用 `uvicorn 文件名:app --reload` 热重载

## Day 4 Embedding + 向量库（04_embedding_chroma.py）

- **Embedding**：把文本映射成高维向量，语义相近则向量距离近；用的是 `text-embedding-v3`（接口 `/v1/embeddings`，和聊天接口不同，模型名不能填 qwen）
- 取向量：`resp.json()["data"][0]["embedding"]`（是 data 不是 choices）
- **Chroma**：`PersistentClient(path="./chroma_db")` 本地持久化，重启数据不丢
- 入库 `upsert`（存在则更新）优于 `add`（ID 重复会崩）；ID 用 `ids=[f"id_{i}"]` 动态生成
- 检索 `collection.query(query_embeddings=[vec], n_results=2)`，返回的 `distances` 是 L2 距离，**越小越相似**
- 输入必须是字符串列表：`get_embedding(docs)`（docs 已是列表）vs `get_embedding([user_query])`（单句要包成列表）

## Day 5 完整 RAG（05_simple_rag.py）

RAG = 检索增强生成，让大模型"开卷考试"：**R（检索）+ A（增强）+ G（生成）**。

1. **解析**：pypdf 的 `PdfReader` 提取 PDF 文本
2. **切块**：按固定长度切（带 overlap 重叠，防止答案被切断在两块交界）
3. **向量化入库**：每块生成 embedding 存入 Chroma
4. **检索**：用户问题也向量化，取最相似的 top2 文档块
5. **生成**：把检索到的块拼进 system prompt（"根据以下文档回答，找不到就说没有，禁止编造"），调聊天模型出答案

- 验证 RAG 生效的技巧：问一个只在 PDF 里存在的冷门事实（如文档中的电话号码），答对说明检索链路通了
- 关键认识：模型"幻觉"可以通过检索真实资料 + 严格 prompt 约束来大幅缓解

## 通用踩坑记录

| 类型 | 案例 | 教训 |
|------|------|------|
| 拼写 | Beared/Bearer、sucess/success、konwledge/knowledge、qurey/query | 拼写错误是最高频的 bug 来源 |
| 字段名 | choice→choices、message→delta、Embeddings→embedding | 接口字段以官方文档为准，别凭感觉写 |
| 缩进 | return 写进 for 循环导致只返回第一条 | 逻辑正确性不只靠语法检查 |
| 重复运行 | chroma add 报 ID 冲突 | 幂等操作用 upsert |
| 编码 | 全角连字符 ‑ 混入代码 | 报错信息里的 \u2011 就是它 |
