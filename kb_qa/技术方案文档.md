# kb_qa 知识库问答智能体 — 技术方案文档

> 课程：Python 应用开发 · 大作业
> 选题：校园学习场景 —— 面向软件工程学生的课程知识库问答智能体
> 一句话介绍：学生上传课程课件后，用自然语言提问，智能体自主检索课件资料、按需调用工具作答，答案标注来源，还能把重点整理成学习笔记文件，并记住用户的学习偏好。

## 一、选题背景与意义

大学生面对多门课程的成堆课件（PDF / PPT / Word），考前想找一个知识点往往要翻几十个文件。本项目把课件集中入库，用户直接用自然语言提问（如"UML 类图有哪几部分？"），智能体从课件中检索相关片段并给出带来源标注的回答，解决了"资料散、检索慢、答案不可信"三个痛点。相比通用大模型直接回答，本项目**只依据上传资料作答**，未覆盖时明确声明，避免模型幻觉误导复习。

## 二、系统架构与模块划分

项目按功能划分模块，入口明确、职责单一：

| 模块 | 职责 | 对应作业参考结构的 |
|---|---|---|
| `main.py` | 程序入口：FastAPI 接口、静态页面挂载、限流 | agent.py（入口） |
| `app/agent.py` | 智能体核心：LangGraph 双层循环编排、模型调用 | agent.py（执行循环） |
| `app/tools.py` | 四个工具函数：检索 / 计算 / 笔记导出 / 长期记忆 | tools.py |
| `app/kb.py` | 资料整理、索引与检索：切片、向量化、混合检索 | materials.py |
| `app/memory.py` | 长期记忆：JSON 读写、按用户隔离 | tools.py（状态保存） |
| `app/logger.py` | 结构化日志 | tools.py（日志） |
| `system_prompt.md` | 系统提示词（外置文件，改提示词不用改代码） | system_prompt.md |
| `examples/` → `data/` | 知识库资料 | data/ |
| `outputs/` | 智能体生成的成果文件 | outputs/ |

技术栈：LangChain + LangGraph（Agent 编排）、Chroma（向量库）、MySQL 8（业务库）、FastAPI + 原生 HTML（前后端分离）、Docker Compose（部署）。

## 三、大模型调用与提示词设计

- **真实 API 调用**：`langchain_openai.ChatOpenAI` 走 DashScope 兼容模式，模型 `qwen3.7-plus`，密钥从 `.env` 读取（不写死在代码里）。
- **系统提示词**（`system_prompt.md`）三段式设计：
  1. **职责**：知识库问答助手，只依据资料作答，未覆盖明确声明并标注"通用知识补充"；
  2. **工具规则**：四个工具的名称、用途、参数格式、使用时机（回答知识题先检索、数学必须用工具算、用户透露偏好时主动记忆、要求导出时生成笔记）；
  3. **输出要求**：严格的 ReAct 格式（思考/行动/行动输入/最终答案），最终答案必须带角标引用（如"……[1]"），编号与检索片段对应。

## 四、工具设计与实现（必做第 2 项）

四个工具均为独立功能的 Python 函数（`app/tools.py`），运行时可观察工具名称、参数与结果摘要（见 `logs/agent.log`）：

| 工具 | 用途 | 参数 | 实现要点 |
|---|---|---|---|
| `search_knowledge` | 知识库检索 | 检索关键词或问句 | 调用 kb.py 混合检索，返回带 `[n] 来源:文件名(第X页)` 前缀的片段 |
| `calculator` | 数学计算 | 算式字符串，如 `2*(3+4)/7` | 用 `ast` 解析并白名单校验运算符，**不使用 eval**（防 prompt injection 执行任意代码） |
| `save_note` | 生成成果文件 | `标题\|内容` | 写 Markdown 文件到 `outputs/`，文件名含时间戳+用户名，内容带来源标注 |
| `save_memory` | 保存长期记忆 | `键\|值` | 调用 memory.py 写 JSON，按用户隔离 |

## 五、智能体循环（必做第 3 项）

采用 LangGraph 状态机实现**内外双层循环**：

- **外层循环（连续对话）**：Web 服务长期运行，每个浏览器会话一个 `thread_id`，用户随时发起新问题；
- **内层循环（迭代任务）**：状态机 `agent → tool → agent → … → save`，agent 节点让模型推理并输出"行动"，tool 节点执行工具并把"观察"写回 scratchpad，循环直到模型输出"最终答案"或到达 `MAX_STEPS=5` 防死循环。

多轮追问的处理：每轮先判断是否有历史，有则先调模型把追问（如"那要带什么材料"）改写成独立问题（"补办校园卡要带什么材料"）再检索，检索命中率显著提升。

## 六、RAG 实现（必做第 4 项 + 加分项）

1. **资料来源明确**：知识库课件为本校课程课堂资料（软件工程与 UML、AI 大模型应用开发等），通过网页上传入库，全部文档在文档管理页可见、可溯源。
2. **索引链路**：读文件（pdf/docx/pptx/txt/md）→ 按字符 500 / 重叠 50 切片 → `text-embedding-v3` 向量化 → 存入 **Chroma**（cosine 距离）→ MySQL 记录切片 id 与文件哈希（哈希去重，同一文件不会重复入库）。
3. **检索链路（加分项：混合检索 + 重排）**：
   - 向量路：Chroma 相似度检索取 top-10，低于相似度阈值 0.40 放弃；
   - 关键词路：jieba 分词 + BM25 取 top-10，强关键词信号线 0.9 兜底；
   - **RRF 融合重排**：两路候选按倒数排名融合（k=60），得到最终 top-K，兼顾语义与精确关键词。
4. **来源标注**：检索片段自带 `[n] 来源:文件名(第X页)`，提示词强制回答带角标引用，前端展示"引用来源"区块，学生可按出处翻课件核对。

## 七、两种记忆（必做第 5 项）

| 记忆 | 实现 | 效果 |
|---|---|---|
| 短期记忆 | LangGraph `MemorySaver` + save_node（保留最近 10 轮） | 多轮追问："那要带什么材料？"能接住上一问 |
| 长期记忆 | `app/memory.py`：按用户存 JSON（`data/memory.json`） | Agent 在对话中识别到偏好/进度就调 `save_memory` 工具记录；**每次提问前 main.py 读取该用户的记忆注入系统提示词**，重启程序后依然记得；提供更新（工具）与清除（页面"🧠 清除记忆"按钮 → `POST /kb/memory/clear`）两种方法 |

## 八、日志系统（必做第 6 项）

`app/logger.py` 用 `logging` 模块输出到 `logs/agent.log`，一行一条，记录四类关键信息：

```
2026-11-19 08:22:39 [INFO] 工具调用 tool=save_note 参数=UML类图的组成部分|… 耗时=0.01s 结果=已保存笔记: outputs/20261119_082239_UML类图的组成部分_testuser.md

```

覆盖作业要求的：请求哪个模型、调用了哪个工具（含参数与结果摘要）、任务耗时、Token 用量。

## 九、结果输出（必做第 7 项）

智能体对话中可直接产出成果文件：用户说"把这个知识点整理成笔记保存"，Agent 调 `save_note` 工具，在 `outputs/` 生成可直接打开查看的 Markdown 学习笔记（含标题、整理时间、用户名、正文与来源标注）。示例：

```
outputs/20261119_082239_UML类图的组成部分_testuser.md
```

## 十、运行结果怎么得到

1. 按README"快速启动"配置 `.env` 并启动（本地 `python main.py` 或 `docker compose up -d --build`）；
2. 浏览器注册登录 → docs.html 上传 `examples/` 的课件 → 管理员在 admin.html 审核通过；
3. chat.html 提问（如"什么是 RAG？它和微调有什么区别？"）→ 观察流式输出的思考/行动过程、带角标的答案与引用来源；
4. 说"记住我在准备期末考试"→ 说"把刚才的回答整理成笔记保存" → outputs/ 出现成果文件；
5. 重启服务后再问"我在准备什么考试" → 智能体凭长期记忆回答（证明 JSON 记忆跨重启生效）；
6. 打开 `logs/agent.log` 查看上述全过程的模型/工具/耗时/Token 日志；
7. 两台设备（PC + 手机）分别登录，A 上传、B 提问，A 的看板与实时动态 3 秒内更新（多端互动）。

## 十一、部署

单机部署：阿里云轻量应用服务器 + Docker Compose（应用容器 + MySQL 容器），公网 IP:8000 直接访问，数据卷持久化（MySQL named volume + chroma_db/uploads 宿主机挂载）。启动命令一条：`docker compose up -d --build`。

## 十二、已知局限

- 上下文压缩：多轮历史仅截断 10 轮，未做摘要压缩；
- 长期记忆为单文件 JSON，高并发场景应换数据库存储；
- token 会话存内存，重启后需重新登录（可换 Redis/JWT）。
